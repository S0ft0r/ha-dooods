# TODO — DOOODS2F: распознавание лиц с домофона

**Статус:** база синхронизирована с DOOODS2 `0.1.18-dev`; alpha-конвейер YuNet/SFace и порог App из `0.1.21-dev` проверены на тестовой камере: при `0.7` найдено одно лицо (331×474 px), последняя задержка 59.42 ms. В `0.1.22-dev` разрабатывается единая App Ingress-страница с приватным буфером кадров, журналом и ручной регистрацией; на стенде новую страницу ещё не проверяли.  
**Рабочая копия:** `local_apps/dooods2f/`.  
**Исходная база:** `local_apps/dooods2/`, версия `0.1.18-dev` (не меняется).  
**Собственная нумерация DOOODS2F:** начать с `0.1.16-dev`; текущая разработочная версия `0.1.22-dev`; `config.yaml` и `APP_VERSION` держать синхронными.  
**Slug:** сохранить `dooods2`, не меняя идентификатор App.  
**Релизы:** не собирать и не публиковать, пока пользователь отдельно не попросит.

## Цель

Добавить в DOOODS2F локальную обработку кадров домофона: сравнивать найденное лицо с галереей вручную зарегистрированных людей и сообщать в Home Assistant о достаточно уверенном совпадении. Это функция уведомления, не управление замком или доступом.

## Зафиксированные решения и границы

- Камера домофона подключена к тестовой HA; пользователь подтвердил RTSP. Face inference и настройка `0.1.21-dev` проверены на `0.7`: в последнем обработанном кадре 1 лицо, bbox 331×474 px, latency 59.42 ms. Сравнение с `0.9` и проверка ложных срабатываний ещё нужны. Производственную Raspberry Pi не использовать для экспериментов.
- Новые образцы добавляются в галерею **только после ручного подтверждения**. Автоматически обучать галерею по результатам собственных совпадений нельзя.
- Для человека можно хранить несколько подтверждённых образцов, снятых в разных условиях: дневной и ИК-режим, погода, ракурс, расстояние, головной убор и изменения причёски. Нечёткие, слишком маленькие или сильно закрытые лица не использовать.
- Основная идентификация должна опираться на лицо, а не на одежду: одежда может меняться и использоваться только как дополнительный контекст.
- Новая функциональность разрабатывается в `local_apps/dooods2f/`; оригинальный `local_apps/dooods2/` не менять.
- Возможные изменения HA-интеграции вне `dooods2f` заранее описывать отдельно и согласовывать. Не расширять текущий scope GitHub Actions без отдельного решения.
- Хранение и обработка — локальные. Не включать облачную отправку кадров или шаблонов лиц без отдельного согласования.

## План работ

### Этап 1 — Проверить источник кадров и выбрать модели

**Промежуточная оценка для целевого стенда (29 октября 2026):**

- Производственная цель: Raspberry Pi 5, 8 GB RAM, архитектура `aarch64`; на нём не проводить эксперименты и не обновлять App ради тестов. Slug `dooods2` сохраняется, поэтому faces проверяется только на отдельной тестовой HA.
- Текущий стенд — VMware Workstation `amd64`. Он подходит для разработки и проверки функциональности; камера домофона может быть подключена к стендовой HA. Такие тесты не подтверждают производительность ARM64 на Raspberry Pi.
- Предварительно начать с CPU-only и одной камеры, обрабатывать кадры по событию/редкими снимками. Пока нет оснований покупать ускоритель или менять сервер.
- Для alpha-прототипа выбрана связка YuNet (детектор) + SFace (embedding) через OpenCV CPU. Это не окончательный выбор production-модели и не разрешение на identity matching; лицензию runtime и весов проверять отдельно.
- Есть внешний ориентир: в независимом тесте Raspberry Pi 5 8 GB с OpenCV 4.10 YuNet+SFace обрабатывали кадр примерно за 74 ms при 640×480 и 204 ms при 1280×720 (пиковая память около 163 MB). Это не тест образа DOOODS2F и не гарантия производительности на HA: версии OpenCV, сборка, охлаждение и нагрузка отличаются.
- Источники: [характеристики Raspberry Pi 5](https://www.raspberrypi.com/products/raspberry-pi-5/); [замер YuNet+SFace на Pi 5](https://tech.swallow-incubate.com/liveness/cortex-a76-opencv-benchmark/); [YuNet model card/license](https://github.com/opencv/opencv_zoo/blob/main/models/face_detection_yunet/README.md); [SFace model card/license](https://github.com/opencv/opencv_zoo/blob/main/models/face_recognition_sface/README.md).

**Дополнительный кандидат: `ageitgey/face_recognition` + dlib (изучен 30 октября 2026; пока не выбран):**

- [x] Python-обёртка `face_recognition` распространяется под MIT; dlib — под Boost Software License 1.0; веса в `face_recognition_models` заявлены как public domain/CC0. Использование технически допустимо при сохранении соответствующих notices; весь стек нельзя обозначать только MIT.
- [x] Библиотека генерирует embedding размером 128. Текущая галерея принимает этот размер, но dlib-векторы относятся к отдельному пространству признаков: обязательно отличать их `model_id`/`model_version` от YuNet+SFace и не сравнивать embeddings разных моделей друг с другом.
- [x] Для Pi без NVIDIA CUDA рассматривать HOG как CPU-вариант; CNN-детектор точнее, но существенно медленнее без CUDA. Значение сравнения `tolerance=0.6` — только начальный параметр для калибровки, не готовый порог для домофона. В документации есть ограничения на распознавание детей и вариативность качества; LFW-бенчмарк не считать гарантией точности на дверной камере.
- [x] Есть существенный packaging-риск: на момент проверки официальный PyPI-пакет `dlib` 20.0.1 опубликован только как source distribution, то есть может потребоваться C++-сборка. `dlib-bin` предлагает сторонние wheels, включая Linux ARM64/x86-64 для CPython 3.10+, но это отдельный пакет и его нужно отдельно закрепить/аудировать; `face_recognition` setup metadata перечисляет classifiers только до Python 3.9. До выбора проверить Python/libc в закреплённом multi-arch образе DOOODS2F и разрешение зависимостей.
- [x] Полный `face_recognition_models` source archive около 100 MB; оценить размер итогового контейнера и возможность не включать ненужные веса.
- [ ] После подключения камеры сравнить dlib/HOG и YuNet+SFace на одних и тех же реальных кадрах: обнаружение маленького/повёрнутого лица, ложные совпадения/пропуски, задержка и RAM на Pi 5. До этого считать `face_recognition` только кандидатом для прототипа, не выбранной production-моделью.
- Источники: [репозиторий и MIT `face_recognition`](https://github.com/ageitgey/face_recognition); [128-D и калибровка threshold](https://github.com/ageitgey/face_recognition/wiki/Face-Recognition-Accuracy-Problems); [ограничения модели](https://github.com/ageitgey/face_recognition); [metadata зависимостей/Python classifiers](https://github.com/ageitgey/face_recognition/blob/master/setup.py); [лицензия dlib](https://github.com/davisking/dlib); [лицензия весов](https://github.com/ageitgey/face_recognition_models); [официальный PyPI dlib](https://pypi.org/project/dlib/); [сторонние dlib wheels](https://pypi.org/project/dlib-bin/); [размер пакета моделей](https://pypi.org/project/face_recognition_models/).

## Критерии готовности первой версии

- Пользователь может вручную зарегистрировать человека и добавить несколько подтверждённых образцов лица.
- Новые обнаружения сравниваются только с этой вручную утверждённой галереей; автоматического пополнения нет.
- Неуверенные результаты не выдаются за совпадение; повторные уведомления ограничены.
- Результат доступен Home Assistant для автоматизации, а все чувствительные данные остаются локальными и защищёнными.
- Проверки проходят на тестовом стенде; исходный `dooods2` и релизные ZIP не меняются.
