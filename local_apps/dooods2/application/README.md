# DOOODS — интеграция распознавания объектов

**DOOODS** — *Dedicated Overhaul Open Object Detection Service*. Независимая интеграция использует домен `dooods`, чтобы не конфликтовать со встроенной интеграцией Home Assistant `doods`.

## Версионирование

Последняя версия интеграции в `manifest.json` — `0.1.21`. Панель содержит вкладку локального JPEG-архива по умолчанию и прежний редактор профилей в «Настройке»; подписи меток редактора переводятся по языку Home Assistant, при этом значения API остаются исходными. После редактирования confidence порядок меток сохраняется. Сообщения статуса находятся в правой колонке под настройками, а кнопка добавления метки — под списком меток. Для каждой камеры в разделе «Настройки» её устройства доступны переключатели распознавания и обработки потока, выбор датчика движения, отдельный периодический интервал сканирования и задержка перед повторной RTSP-проверкой после положительной детекции. App `DOOODS2` версии `0.1.17-dev` не публикует веб-интерфейс через Ingress; native-панель интеграции продолжает использовать защищённый API App.

## Первоначальная настройка и параметры

- Первоначальный Config Flow состоит из URL/ключа, выбора камер и `output`/архива; общего интервала в Config Flow и Options Flow нет. Он автоматически выбирает первый настроенный детектор с меткой `person`; если такого нет, настройка останавливается с понятной ошибкой. Каждая камера получает отдельный числовой интервал в разделе «Настройки» её устройства; исходное значение — 30 секунд. Сохранённый старый общий интервал игнорируется и не переносится на камеры. Legacy-параметры по умолчанию — `person`, confidence `50`, вся область кадра.
- При наличии capabilities `profiles` и `polygon_zones` интеграция при загрузке записи идемпотентно обеспечивает отдельный профиль каждой выбранной камере. Начальный профиль содержит одну полноэкранную зону «Зона 1», метку `person` и порог `50`. Если старое тестовое назначение делит профиль между несколькими камерами, для последующих камер создаются отдельные профили с копией исходных зон. На сервере без Profiles API профиль не создаётся: распознавание продолжает работать с legacy-настройками.
- Профили нельзя назначать вручную, отвязывать, создавать или удалять из HA. Admin-only панель DOOODS оставляет список камер в неизменном левом столбце и помещает TabView во второй и третий столбцы. По умолчанию открывается «Архив»; вкладка «Настройка» показывает прежний редактор: кадр, зоны и настройки с явным сохранением. В списке камер показывается только HA `friendly_name`, без `entity_id`.
- Кадр автоматически запрашивается у выбранной сущности камеры через защищённый HTTP endpoint Home Assistant. Пользователю не нужно выбирать источник, загружать JPEG или связывать preview с профилем. Недоступный кадр показывается как ошибка предпросмотра; профиль не отмечается как успешно сохранённый. У профиля всегда остаётся минимум одна зона: последнюю нельзя удалить, пустой список также блокируется серверной обработкой панели. Кнопка «По умолчанию» меняет только геометрию выбранной зоны на границы всего кадра (0–1); название, метки, пороги и остальные настройки сохраняются.
- API-ключ хранится в настройках записи HA и используется только в серверных запросах `doods-auth-key`. Он не попадает в URL, HTML/JavaScript или browser storage. Профильные команды WebSocket и кадр доступны только администратору; браузер передаёт только ID записи и сущность камеры.
- Для каждой камеры в разделе «Настройки» её устройства создаются переключатель «Распознавание», селектор «Источник движения» и отдельные числовые интервалы сканирования и повторной RTSP-проверки. В селекторе можно выбрать рабочий binary_sensor HA, RTSP-поток (если он поддерживается сервером) или «Не использовать». Выбранный источник действует напрямую: выбор HA-сенсора выключает RTSP, а выбор RTSP выключает триггер HA; при недоступности выбранного сенсора fallback не включается. При первоначальном выборе по умолчанию предпочтителен рабочий HA-сенсор, а при его отсутствии выбирается RTSP, если сервер поддерживает gate. Отключение «Распознавания» прекращает все проверки камеры. Интервал сканирования по умолчанию — 30 секунд, задержка повторной проверки после положительной RTSP-детекции — 5 секунд (0–3600; 0 отключает cooldown). При активном RTSP gate первый scan запускается сразу, во время cooldown сохраняется самый свежий RTSP candidate, а следующий scan допускается только при новом candidate после окончания паузы. Если gate стал idle, отложенный scan не запускается и presence polling не выполняется; периодический scan interval остаётся независимым механизмом. Если после выбора HA-источника сенсор уже находится в состоянии `on`, сканирование запускается сразу; обычный переход выбранного сенсора в `on` запускает только связанную камеру и не сбрасывает периодический таймер.
- Профильная фильтрация выполняется на сервере. Интеграция перечитывает метки профилей раз в минуту; новые бинарные сенсоры добавляются без перезагрузки, а затронутая камера запускается на повторное сканирование. Сенсоры удалённых меток удаляются из платформы и реестра HA. При старте также удаляются устаревшие записи реестра. Если метка вернётся, сенсор создаётся снова и HA может восстановить прежний entity ID.
- Options Flow не проходит последовательно настройки датчика или интервала каждой камеры: их можно менять в разделе «Настройки» соответствующего устройства. Общая форма объединяет выбор камер, детектор, область распознавания и параметры архива; тайм-аут, confidence и выбор меток в Config Flow/Options Flow не редактируются. При временной недоступности сервера имя детектора можно ввести вручную.
- Первый скан запускается фоновой задачей после события `homeassistant_started`, когда платформы камеры уже получили время на загрузку; запуск Home Assistant не блокируется. Одноразовый listener снимается при выгрузке только если ещё не был вызван. Задача первого сканирования отслеживается координатором, отменяется и ожидается при остановке. При ошибке камера/сервер опрашиваются повторно с интервалом 5 секунд с экспоненциальным увеличением до 5 минут, даже если периодический опрос отключён. После успешного сканирования повторы отменяются и задержка сбрасывается.

Адрес и ключ хранятся в данных записи, остальные параметры — в настройках интеграции. Ключ отправляется только в заголовке `doods-auth-key`, не в URL. Старый DOODS2 может не проверять его; DOOODS2 Overhaul с настроенным `server.auth_key` проверяет ключ для защищённых API.

## Ручное сканирование

Действие Home Assistant **`dooods.scan`** ставит выбранную камеру или камеры в очередь внеочередного сканирования. Оно запускает те же проверки, что расписание и датчик движения, но не зависит от них и не изменяет периодический таймер. Действие возвращается после постановки запроса в очередь и не ждёт завершения сканирования.

В редакторе автоматизаций или **Инструменты разработчика → Действия** выберите действие `dooods.scan` и укажите камеры, которые уже выбраны в настройках интеграции `dooods`. Пример YAML для нескольких камер:

```yaml
action: dooods.scan
target:
  entity_id:
    - camera.front_door
    - camera.garage
```

Выбор камеры, не настроенной ни в одной загруженной записи DOOODS, возвращает понятную ошибку. Служба не использует старую платформу `image_processing` и не заменяет `image_processing.scan`.

## Устройства и сущности

Интеграция регистрирует одно виртуальное родительское устройство сервера DOODS2. Для каждой выбранной камеры создаётся дочернее устройство DOOODS, к которому относятся бинарные сенсоры меток, сводный сенсор объектов и сущность последнего размеченного изображения. В новых версиях Home Assistant используется `ChildDeviceInfo`; для старых версий сохранена совместимая связь через родительское устройство.

- Бинарный сенсор метки: `on` — метка найдена в последнем успешном сканировании; `off` — сканирование успешно, но метка не найдена.
- Сводный сенсор показывает общее число выбранных объектов. Атрибут `detections` содержит метку, уверенность и нормализованную рамку (`top`, `left`, `bottom`, `right`); также доступны счётчики и максимальная уверенность по меткам.
- Для каждой камеры создаются шесть диагностических RTSP gate-сенсоров: состояние (`connecting`, `idle`, `active`, `reconnecting`, `disabled`), последний motion score, максимальный score за последний интервал, число проверенных кадров, число кадров-кандидатов и время последнего перехода в `active`. У сенсоров score есть атрибут порога (`0.004`); счётчики относятся к текущему worker и сбрасываются при его перезапуске. Если используется HA motion-сенсор, RTSP gate остаётся `disabled`, а `active_source` показывает выбранный источник. Все шесть диагностических сущностей по умолчанию отключены; существующие сущности отключаются одноразовой миграцией. Их можно включить вручную в реестре HA.
- Сущность изображения сохраняет последний размеченный кадр с обнаружениями, прошедшими фильтры. Пустой скан обновляет счётчики сенсоров, но не перезаписывает JPEG и время его получения.
- Ошибка получения снимка или запроса делает сущности только соответствующей камеры недоступными, а не показывает ложное отсутствие объектов.
- При удалении камеры в мастере параметров после перезагрузки удаляются её дочернее устройство и устаревшие записи сущностей.

## Локализация подписей на изображении

- Если DOOODS2 Overhaul объявляет capability `localized_annotations`, интеграция передаёт в запросе язык установки Home Assistant (`annotation_locale`). Для русского/английского стандартные подписи на JPEG переводятся; неизвестные пользовательские метки остаются исходными, если в настройках App не задано отображаемое имя.
- Перевод меняет только текст на изображении. Метки `label`, сенсоры, фильтрация, атрибуты обнаружений и архивные данные остаются в исходном виде.
- Сущность изображения одна на камеру, поэтому кадр размечается на языке конфигурации всего Home Assistant, а не на разных языках отдельных пользователей. Старые серверы, не объявившие capability, получают запрос без нового поля и продолжают работать как прежде.

## Архив размеченных кадров

- Поле `file_out` задаёт один корневой каталог архива. Пустое значение отключает запись; относительный путь считается от каталога конфигурации Home Assistant. Если в старой настройке было несколько строк-шаблонов, укажите один каталог: предыдущие версии эти шаблоны сохраняли, но не использовали.
- Интеграция сохраняет только JPEG с хотя бы одной детекцией, прошедшей активные фильтры. Пустые сканы, ошибки камеры и кадры без принятой детекции не попадают в архив.
- Для каждой записи и камеры создаются отдельные подпапки, далее — каталог даты и JPEG с уникальной временной меткой. Пример: `<каталог>/dooods/<запись>/<камера>/<дата>/dooods_<UTC-время>_<суффикс>.jpg`.
- `archive_max_count` ограничивает число архивных кадров **на камеру**; значение по умолчанию — 10, `0` отключает лимит количества. `archive_max_age_days` ограничивает возраст; по умолчанию `0` (без ограничения). Если заданы оба лимита, удаление срабатывает при превышении любого.
- Рядом с каждым новым JPEG сохраняется sidecar JSON с каноническими метками, confidence и, если сервер передал его, ID зоны. При удалении JPEG по квоте его sidecar удаляется вместе с ним. Старые кадры без sidecar не классифицируются задним числом.
- Очистка запускается при старте HA, после сохранения кадра и ежедневно при включённом ограничении по возрасту. Удаляются только JPEG и sidecar, созданные интеграцией в подкаталоге текущей записи; другие файлы корневого каталога не трогаются. Запись и очистка выполняются вне event loop.
- Вкладка «Архив» показывает четыре миниатюры в строке и использует cursor-пагинацию по 12 кадров с кнопкой «Показать ещё»; отдельные страницы и изменение размера страницы не добавляются. Селектор предлагает «Все» и метки, настроенные для выбранной камеры; выбранная метка фильтрует кадры, новые сначала. Старые JPEG без metadata видны только в «Все». Метки и наивысший confidence отображаются на карточках.
- Пока открыта вкладка архива, первая страница проверяется каждые 15 секунд. Новые кадры вставляются автоматически, если пользователь остаётся на первой странице; после загрузки старых страниц или при открытом увеличенном кадре список не сдвигается, а появляется индикатор «Есть новые кадры». Его нажатие возвращает к свежей первой странице. Периодическая проверка запрашивает только список метаданных; новые JPEG загружаются по мере появления, а возврат к первой странице загружает её миниатюры заново. Список не раскрывает файловые пути, а выдача изображения повторно проверяет права администратора, запись и выбранную камеру.
- Каталог `/config/www` может публиковать изображения через `/local`; для приватных кадров укажите каталог, не раздаваемый как статический веб-контент. Смена или очистка `file_out` не удаляет старый архив; он остаётся в прежнем каталоге и управляется вручную.

## Предпросмотр камеры

- Новый встроенный редактор профиля получает актуальный кадр непосредственно у выбранной HA-сущности через admin-only HTTP view. Кадр не загружается в App, не сохраняется в профиль или browser storage и не требует ручного выбора источника.
- Если кадр недоступен или камера возвращает неподдерживаемый формат, панель показывает ошибку вместо ложного состояния успешной загрузки. Сохранение зон при этом выполняется только после явного действия и подтверждения сервером.
- Отдельный временный preview API DOOODS2 остаётся для старых/standalone App-сценариев. Если capability `camera_preview` включён, координатор может отправлять JPEG сканирования в `PUT /preview/{source_id}` фоново, не задерживая распознавание. Эти кадры не используются новым редактором профилей.
- Передача в standalone preview ограничена одним кадром на камеру за 30 секунд; принимаются JPEG до 4 MiB. `source_id` — стабильный непрозрачный SHA-256-идентификатор записи и камеры. Сам `camera_entity_id` API не получает, отображаемое имя передаётся отдельно в Base64URL-заголовке `X-Source-Name-B64`.

## Переводы и иконки

Пользовательские имена сущностей и устройств берутся по ключам `translation_key`, а не задаются фразами в Python. Комплект содержит английские резервные переводы `translations/en.json` и русские переводы `translations/ru.json`; `strings.json` хранит исходные строки. Документация проекта ведётся на русском языке.

Иконки вынесены в стандартный для Home Assistant файл **`icons.json`**. Для меток COCO и ряда распространённых меток добавлены отдельные ключи перевода и MDI-иконки. При точном соответствии используется одноимённая иконка; если такого имени нет, выбрана наиболее похожая по силуэту и содержимому. Например, `person` → `mdi:human`, `stop sign` → `mdi:octagon`, `sports ball` → `mdi:soccer`, `baseball glove` → `mdi:boxing-glove`, `banana` → `mdi:food-croissant`. Для неизвестной метки сохраняются исходное имя и общая иконка `mdi:shape-outline`.

## Будущие задачи

- Настраиваемые пороги уверенности для каждой метки в legacy-режиме без профиля; профили Overhaul уже задают метки и пороги отдельно для зон.
- В старом DOODS2 сервер может игнорировать `auth_key`; считать API защищённым только если серверная версия действительно проверяет ключ (например, Overhaul с настроенным `server.auth_key`).
