# DOOODS2 — документация

DOOODS2 — локальный сервис распознавания объектов для Home Assistant. Он работает совместно с интеграцией **DOOODS**, которая связывает сервис с камерами, предоставляет сущности и настройки профилей. Распознавание лиц и компенсация освещения лица являются экспериментальными функциями.

Документация относится к основному App **0.1.36.1**. Доступные возможности также зависят от версии интеграции.

## Первоначальная настройка

1. Установите и запустите приложение DOOODS2. При первой установке сборка может занять несколько минут.
2. На вкладке **«Конфигурация»** проверьте настройки приложения. По умолчанию сервер слушает `0.0.0.0:8080` внутри контейнера; эти значения нужны для работы Ingress.
3. Если `server.auth_key` оставлен пустым, приложение при первом запуске создаёт случайный ключ и сохраняет его в настройках App через Supervisor. Укажите этот ключ при настройке интеграции DOOODS. Не помещайте ключ в URL и не публикуйте его в журналах или скриншотах.
4. Установите интеграцию DOOODS, перезапустите Home Assistant и добавьте её через **Настройки → Устройства и службы → Добавить интеграцию**. Укажите адрес сервиса и API-ключ, затем выберите камеры и настройте обработку.
5. Профили и зоны камер настраиваются через панель интеграции. Страница **faces** доступна через Ingress и боковое меню приложения, если функция лиц включена.

После изменения настроек приложения сохраните их и перезапустите App. Изменения параметров лица применяются после перезапуска.

## Профили, зоны и движение

Профили позволяют задавать правила распознавания для камер и выделять зоны на изображении. В совместимой версии интеграции для каждой зоны можно нарисовать исключающие маски. Объект исключается из данной зоны, только если его рамка целиком находится внутри одной из её масок. Маска не распространяется на другие зоны.

Источником движения может быть внешний датчик Home Assistant или детектор движения RTSP. Настройка источника и режимов обработки выполняется в интеграции; доступность зависит от конфигурации камеры. Изображение и результаты обнаружений предоставляются интеграцией как сущности Home Assistant.

## Распознавание лиц

Функция экспериментальная. Её результаты зависят от качества и размера лица в кадре, освещения и подобранных порогов. Сходство — оценка модели, **не вероятность личности**. Не полагайтесь на него как на единственный фактор для критичных действий или управления доступом.

В интерфейсе **faces** можно работать с галереей эталонов и диагностикой. Для распознавания необходимо включить функцию лиц и настроить соответствующую обработку камеры. Доступность кадров зависит от источника и настроек детектирования.

Основные параметры раздела `face`:

| Параметр | Назначение и значение по умолчанию |
| --- | --- |
| `enabled` | Включает функцию лиц; по умолчанию `true`. При выключении данные не удаляются, но доступ к функциям галереи, включая импорт и экспорт, закрыт. |
| `diagnostics_enabled` | Диагностика лиц; по умолчанию `true`. При выключении распознавание продолжает работать, но новые диагностические кадры и журнал не записываются, а управление галереей через API закрыто. Ранее сохранённые данные не удаляются. Страница показывает ограниченную сводку без имён и изображений. |
| `max_match_faces` | Максимальное число крупнейших лиц, сравниваемых независимо в одном кадре: от 1 до 5, по умолчанию 3. Увеличение может повысить нагрузку и задержку. |
| `yunet_score_threshold` | Порог уверенности обнаружения лица YuNet: 0.1–1.0, по умолчанию 0.9. Уменьшение может увеличить число находок и ложных срабатываний. |
| `face_match_threshold` | Порог сходства SFace: 0.1–1.0, по умолчанию 0.4. Ниже порога лицо считается неизвестным. |
| `face_match_min_gap` | Минимальный отрыв от следующего человека: 0.0–0.5, по умолчанию 0.1. Если отрыв недостаточен, результат обозначается как неоднозначный (`ambiguous`). |
| `min_face_width`, `min_face_height` | Минимальные размеры лица в пикселях для попадания кадра в диагностический буфер; по умолчанию 100 × 100. |

Совместимая интеграция может формировать отдельные события `dooods_face_match` для совпадений и неоднозначных результатов. Публикация событий включается в настройках интеграции; неизвестные лица таких событий не создают. Неоднозначный результат не следует использовать для разблокировки.

### Компенсация освещения лица

`face.illumination_compensation` по умолчанию выключена. При включении тёмное выровненное изображение лица осветляется перед сравнением SFace. Поиск лиц YuNet использует исходный кадр; исходные изображения и эталоны не изменяются.

- `illumination_threshold` — порог яркости 0–255, по умолчанию 60. Обрабатываются лица с яркостью ниже порога; `0` отключает обработку.
- `illumination_gamma` — гамма 0.3–0.9, по умолчанию 0.45. Меньшее значение даёт более сильное осветление.

Проверяйте результат на своих дневных и ночных кадрах: изменение освещения может как улучшить, так и ухудшить совпадения. При необходимости заново подберите пороги. Изменения применяются после перезапуска App.

При включённой диагностике интерфейс может показывать исходный кроп, JPEG-копию выровненного лица до компенсации, JPEG-приближение входа SFace после обработки и эталон. Обе копии относятся к одному обнаружению, сохраняются в приватном ограниченном буфере и удаляются вместе с записью; они не являются побайтовой копией входа модели. Для старых записей изображение до компенсации недоступно. Для старых записей и результатов ручного rematch изображение входа SFace может отсутствовать.

## Разметка и детектор

В разделе `doods` находятся настройки детектора и оформления изображения:

- `boxes` — рамки и подписи объектов, их цвет, толщина, отступ и объединение перекрывающихся рамок одного класса. Эти настройки изменяют изображение, а не результаты API или проверку зон.
- `regions` — отображение зон и областей, цвет линий и подписи.
- `globals` — диагностическая разметка общих порогов; список порогов показывается при уровне журнала Debug.
- `annotation_labels` — необязательный JSON-словарь пользовательских подписей по языкам; исходные метки API не изменяются.
- `detectors` — список детекторов и их моделей. По умолчанию используется CPU-модель TFLite с двумя потоками. Меняйте пути модели, метки и аппаратное ускорение только при наличии совместимой конфигурации.

Раздел `logger` управляет подробностью журнала. В разделе `server` параметры `metrics` и `trace` предназначены для диагностики; по умолчанию они выключены. `profiles_file` указывает на файл профилей в постоянном каталоге данных App; без необходимости путь менять не следует.

## Если что-то не работает

- **App не запускается:** откройте вкладку «Журнал», проверьте сообщения об ошибках и корректность изменённых параметров. После изменений перезапустите App.
- **Интеграция не подключается:** проверьте, что App запущен, указан правильный адрес и в интеграции задан тот же API-ключ. Не публикуйте ключ при обращении за помощью.
- **Нет обнаружений:** проверьте доступность камеры и кадров, настройки источника движения, выбранные объекты и зоны. Для масок убедитесь, что рамка объекта не попадает целиком в исключающую область.
- **Нет результатов лиц:** убедитесь, что `face.enabled` включён, обработка камеры настроена, в галерее есть подходящие эталоны, а лицо достаточно хорошо видно. Проверьте пороги и журнал; готовность моделей сама по себе не подтверждает обработку кадров.
- **Диагностические изображения не отображаются:** проверьте `face.diagnostics_enabled`. При его отключении отображается только ограниченная сводка; изменение требует перезапуска.
- **RTSP не подключается:** проверьте адрес и доступность потока именно из окружения приложения. `127.0.0.1` внутри контейнера указывает на сам контейнер, а не автоматически на Home Assistant или камеру.

О проблемах сообщайте в [репозитории проекта](https://github.com/S0ft0r/ha-dooods/issues), приложив описание, версии интеграции и App и относящиеся к проблеме сообщения журнала без секретов и личных данных.
